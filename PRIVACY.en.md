The software needs no account, and the developer has no server.
2. **Third-party model services.** To use the software you select and connect to a third-party model service yourself: DeepSeek, the Kilo model (a model gateway service provided by Kilo AI), or a custom model service compatible with the OpenAI or Anthropic API format that you add under "Settings · Models". When you use any third-party model service you must comply with that provider's user agreement, terms of service and privacy policy; the fees, service availability and data handling that come with it are agreed and borne by you and that provider. When web search is used, the search terms are sent to the model service that provides the search; when the page-reading feature is used, the software visits the relevant web pages itself; when an external tool service you added yourself is used, the relevant content is sent to that service as the task requires.

## How your data is handled

The section above is the notice itself. This section is what actually happens in version 0.3.0: where the data sits, when it leaves your computer, and who it goes to. This version can use three kinds of model: DeepSeek, the Kilo model, and the custom models you add under "Settings · Models" (OpenAI- or Anthropic-format endpoints). The "third-party model service" in the notice above can be any of them in this version. The Chinese version of this file is `PRIVACY.md` in the same folder.

### In one sentence

Sidemate runs only on your own computer. **There are no accounts and no server of ours**: no usage statistics, no telemetry, no crash reporting, and nothing reaches the developer. The only things that leave your computer are the ones listed under "When it goes online, and to whom" below.

### Where the data is kept on your computer

Everything sits in one directory: `%LOCALAPPDATA%\sidemate\` (the Windows per-user data directory, under your own account).

- `model.json`: the models and endpoint addresses you configured, plus the switches; **the keys are in here too**.
- `ability.json`: the switches for skills, web search and page reading.
- `mcp.json`: the external tool services you added; **the keys are in here too**.
- `useragreement.json`: your agreement to the "Kilo Model Terms of Use" (version, time, two ticks); never uploaded.
- `news.json`: your news topics (name, what you want to follow, time).
- `skills\`: skills you imported yourself, and skills you confirmed installing from a conversation.
- `tasks\<number>\`: one folder per task (the name is the date and time plus two digits, e.g. `20261116193042`). Inside it: the finished files at the root, `received\` holds the copies of the files you gave it, and `.sidemate\` holds the conversation record and the working files.
- `news\<topic>\<date>\`: the news that was generated.
- `data\`: the logs (`task.log` task log, `pet.log` island log, `news.log` news log, `settings.log` settings window log), the usage (`usage.json`), the recently used folders (`recent.json`), the images and long text you pasted into the input box but have not sent yet (`paste\`), and the crash records (`crash\`).
- `dsh\`: the home directory of the background program dsh (its configuration, logs and runtime cache).
- `temp\`: temporary files.
- `electron\`: the program's own runtime cache.

All of these paths are on your own computer. There is no account system, so there is no sign-up, no login and no cloud profile. The directories left by older versions (the "桌伴" folder in your home directory, the old LocalLow directory and `%APPDATA%\sidemate`) are not read, not moved and not deleted by this version.

### How your keys are stored

The keys you enter in the first-run window or in the settings are kept on this computer only, in `model.json` / `mcp.json`; there is no separate directory for keys. A key is used only when a request is sent to the service it belongs to. Keys are never written to a log, and the interface shows only the first and last few characters, so you can tell which key it is.

### When it goes online, and to whom

Sidemate itself listens on no port and exposes no service. Only these things reach the network:

1. **While working**: Sidemate sends the conversation of this task, the content of the files the model read, and the images in the task, along with the conversation, to the model you chose: DeepSeek (`https://api.deepseek.com/anthropic`, with your DeepSeek key), the Kilo model (`https://ai-gateway.kilo.ai/api/v1`; the content is processed by Kilo AI and the model service providers it calls; where it is processed and whether it is recorded follow Kilo AI's terms; see the "Kilo Model Terms of Use"), or a custom model you added (the address you entered, or the one a preset filled in, with that entry's key). The background program dsh also makes one extra model call to give the task a name. Only give it files you are willing to hand to that provider.
2. **Web search**: when the task needs to look something up, the background program dsh searches through DeepSeek's search service (this needs a DeepSeek key; without one it does not search). The **search terms are sent to DeepSeek's search interface**. You can switch it off under "Settings · Abilities".
3. **Reading a page**: dsh visits that page itself and takes the text out of it; the page address does not go through a third-party model service. This can also be switched off under "Settings · Abilities".
4. **External tool services**: the external tool services you added and switched on under "Settings · Abilities" may be called by the model during a task; the call sends what it needs (which may include text from the task), together with the key you gave that service, to that service's address. Clicking "Test" there also connects to that address once.
5. **News**: if you added topics under "Settings · News", at the set time (or when you click "Generate now") Sidemate sends the topic's description to DeepSeek to search the web and write the news; the result is kept on this computer.
6. **Installing a skill**: only after you ask for a skill in a conversation and click install on the confirmation card does Sidemate download it from GitHub (`api.github.com`, `raw.githubusercontent.com`). No other address is used.
7. **Clicking "Test" or "Test and save"**: it sends one very short test request (the content is `hi`, and only a few characters of reply are asked for) to the endpoint you are testing, to check whether the key works; for a custom model it first requests that endpoint's model list once. This uses a very small amount of quota.

There is no other outbound traffic.

### Two uploads are switched off

The background program dsh has two features that hand content to DeepSeek's official interface: **uploading session logs** and **uploading the plugin inventory**. Sidemate switches **both off**, and as of 0.3.0 nothing is uploaded that way: your conversation records stay on this computer, and the list of plugins Sidemate installed is not reported anywhere.

### Crash records stay on this machine and are not uploaded

If the background program fails to start or exits in the middle of a task, Sidemate leaves a crash record in `data\crash\`: the time, the exit code, the last 200 lines of the background program's output, the number and state of the conversation that was running (no conversation content), and the versions of Sidemate and dsh. That record **only exists on this computer and is never uploaded**; the directory keeps the most recent 20 records and drops the older ones.

### No automatic updates, no telemetry, no crash reporting

- **No automatic update check**: there is no update mechanism in the software (it does not check for updates, does not download an installer and does not show an update prompt). To get a new version, download and install it yourself from the release page.
- **No telemetry**: the telemetry built into the background program dsh is **switched off**; it is always started with `DSH_TELEMETRY_MODE=DISABLED` and `DSH_TELEMETRY_DISABLED=1`. Sidemate does not report usage statistics either.
- **No crash reporting**: the software neither collects nor uploads crash information. If something goes wrong, the logs stay on this computer, where you can read them; nothing is sent anywhere.

### "Get a key" and other links

The links behind "Get a key" in the first-run window and the settings open the model provider's official pages (for example DeepSeek's `https://api-docs.deepseek.com/zh-cn/`) in **your computer's default browser**; "Source" under "About" opens the source repository on GitHub; links in the task window's replies are also handed to the default browser. That is all they do: nothing is collected or reported about what you do on those pages, and the program does not even know whether you clicked.

### Usage is only kept on this machine

The numbers under "Settings · Usage" (the total for this month and the usage of the last 10 tasks) are worked out from a local `usage.json` file: one record per task, with the task name, the time, the usage numbers and the number of web searches; no unit prices, no money maths. That record is never uploaded, never synced and not tied to any account. Delete it and it never happened.

### Your originals

Before working, Sidemate **copies** your files into that task's workspace and works on the copies; the finished files go into that task's folder. While working, the model's file writes and edits are checked by path by the background program dsh and are only allowed inside the workspace; a command that goes outside the workspace asks you first (the task window shows a permission card: allow once / allow for this task / refuse). This restriction comes from dsh's own sandbox; Sidemate no longer adds a system-permission layer of its own on top, so it **cannot guarantee** that the model will never read or change files outside the workspace. Back up important files first, and only give it files you are willing to hand to the model.

### Uninstalling

The uninstaller asks once, "Uninstall Sidemate?", with one option that is **unticked** by default: "Also delete all configuration and records (including the files generated in your tasks; once deleted they cannot be recovered)". If you tick it, the whole `%LOCALAPPDATA%\sidemate\` directory is deleted (settings, conversation records, task files, logs and crash records are all in it, and cannot be recovered afterwards); if you leave it unticked, only the program is removed. A silent uninstall does not ask and deletes nothing. The automatic uninstall that runs while installing a new version deletes nothing either. The directories left by older versions are not touched.
