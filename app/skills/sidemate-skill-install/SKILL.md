# 找一个技能，先给用户看一眼方案

这件事只做一半：**只写方案，不下载、不安装**。桌伴会把方案变成一张确认卡，
上面写清从哪里下、装什么、要不要联网；**用户点了「装上」，桌伴才自己去下载**。

## 不做的事（最要紧）

- **不下载任何文件**：不许用 web_fetch 取仓库里的文件，不许用 bash 或 PowerShell 拉文件。
- **不往工作区写脚本**：不把第三方的 .py / .js / .sh 写进工作区，也不写进技能目录。
- **不往 `~/桌伴/技能/` 里拷东西**：装不装由用户在确认卡上点。

## 找什么样的技能

1. 用联网搜索找公开仓库里的技能。一个技能就是一个**带 `SKILL.md` 的文件夹**，不是单个文件，也不是一堆脚本。
2. 挑一个：
   - 许可证允许分发（MIT、Apache-2.0 这类）。
   - 最近一年内有更新。太久没人管的不要。
   - 文件少而简单：一份 `SKILL.md` 加几个脚本最好。几十个文件、一堆依赖的不要。
3. 只有要装程序、要登录、要密钥的技能不要。如实说「没找到合适的」。
4. 找不到合适的就如实说找不到。**不要自己编一个技能充数**，也不要拿自己写的文件假装是别人的技能。

## 怎么写方案

在工作区里建一个文件夹 `pending-plans/<id>/`，里面放一份 `plan.json`（这是方案，不是脚本）：

```json
{
  "name": "Markdown 转 PDF",
  "source": "https://github.com/某作者/md2pdf-skill",
  "ref": "main",
  "path": "",
  "license": "MIT",
  "updated": "2026-11-11",
  "does": "把 Markdown 转成 PDF"
}
```

- `<id>`（文件夹名）：只能用小写字母、数字和短横线，比如 `md2pdf-skill`。
- `name`：中文名，用户在确认卡上看到的名字。
- `source`：仓库地址，必须是 `https://github.com/作者/仓库` 这样的 GitHub 公开仓库。
- `ref`：分支或标签；不知道就写 `main`。
- `path`：技能在仓库里的位置，仓库根目录就写空串；仓库里有好几个技能时写清楚是哪一个。
- `license`：仓库的许可证。
- `updated`：仓库最近一次更新的日期，`YYYY-MM-DD`。
- `does`：一句话说这个技能会做什么。

这几个字段都要写（`path` 可以是空串）。查不到的就写你能确认的，别编。

## 收尾

写完方案只回一句：

> 找到一个合适的。装之前先给你看一眼：

不要下载，不要安装。桌伴会把方案变成确认卡，用户点了才真的去下载；用户不点，桌伴什么都不会下。
